## Priority Issues

[P0] The name exists nowhere as text.
HeroSection.tsx:22 renders an empty div with the name painted into a 1.04MB opaque PNG. aria-label on a bare div (role=generic) is discarded by screen readers. "Divyam Jha" appears zero times in the rendered DOM.
Why: no indexed heading for the person the site is about; Ctrl+F, selection, translation all fail; mix-blend-mode + background-image means the printed page has no name on it. LCP element is CSS-discovered, unpreloaded, no srcset possible, 1382px source in a 380px box.
Fix: real <h1>Divyam Jha</h1>; art as <img alt=""> beneath. AVIF/WebP at 760px and 380px, fetchpriority="high", link rel=preload. Promote each .section-label div to <h2>.
Command: /impeccable harden

[P0] The marquee cannot be stopped, and a third of it is broken.
index.css:440-458 infinite 35s translate, pause rule commented out at :446-449. NO prefers-reduced-motion anywhere in the codebase - not the marquee, not scroll-behavior:smooth, not the eight framer-motion sections. Icon key mismatch leaves 5 blank slots.
Why: WCAG 2.2.2 flat failure; 2.3.3 for the fades. Five empty boxes reads as a build error on the section whose job is to look competent.
Fix: uncomment hover-pause, add visible pause control, wrap keyframes + framer variants in prefers-reduced-motion. Lowercase icon keys with text fallback. aria-hidden on the duplicated track half (TechStackSection.tsx:56).
Command: /impeccable animate

[P1] Contrast fails across the tokens doing the most work. (ratios independently recomputed)
--text-tertiary #9ca3af on #f5f5f7 = 2.33:1 (View Full Stack, marquee labels, every date/org line).
--text-secondary #6b7280 on #f5f5f7 = 4.44:1 (all 14-15px body copy).
--accent #3b82f6 on #f5f5f7 = 3.38:1 (the only CTAs).
dark --text-tertiary #71717a on #09090b = 4.12:1.
No rule using these tokens reaches the large-text threshold; all resolved sizes are 11-16px.
Why: the two disclosure controls and the only call to action are the three least legible elements.
Fix: --text-secondary -> ~#575d6a, --text-tertiary -> #6b7280 (move .view-more-btn to --text-primary), --accent -> ~#1d4ed8. Add :focus-visible - 961 lines of CSS contain zero focus styles.
Command: /impeccable colorize

[P1] The forced light default is not defensible as built.
ThemeToggle.tsx:9 falls back to 'light' with no prefers-color-scheme read; index.html hardcodes theme-color #F5F5F7; no pre-paint script, so returning dark-mode visitors get a white flash.
Why: committing to light is a real position, but this keeps a full dark theme, ships a 907KB dark PNG, then refuses both when the OS asks. Hands a dark-mode phone a full-brightness 1MB white image.
Fix: either delete the dark theme and its PNG, or three-state (light/dark/system) with a blocking inline script and per-scheme theme-color.
Command: /impeccable harden

[P2] The best writing on the site is unreachable.
InBetweenSection.tsx is fully implemented and styled (index.css:98-105, 389-403) and never imported by App.tsx. The BrainExpo pivot (data.ts:34-50) appears nowhere.
Why: the only content answering "how does this person think", which is the only question a portfolio exists to answer.
Fix: mount between Projects and Experience. Copy-edit first (mixes \n\n escapes with literal indentation); .content clamp is 72px and cuts it mid-sentence.
Command: /impeccable layout

[P2] mix-blend-mode is a load-bearing assumption with no fallback.
Both PNGs are opaque; the plate only disappears because darken/lighten cancels against exactly #f5f5f7 / #09090b. forced-colors ignores blend modes. CSS aspect-ratio 1382/1138 does not match the dark asset (1381x1139).
Fix: export both with real alpha, drop mix-blend-mode entirely.
